# Participant Runbook

## Phase 1 — Qualify

Run preflight, read the entire case, establish team roles and record assumptions. Define the measurable problem and compare process redesign, rules, analytics and master-data repair before choosing AI. Do not begin with a model or agent.

## Phase 2 — Investigate

Build an evidence register across all 84 injects. Map object identity, authority, effective date, jurisdiction, units, terminology, time precision, lineage, access and validation state. Preserve intentional contradictions and distinguish packaging integrity from business-data quality.

## Phase 3 — Specify

Define intended and prohibited uses, human decision rights, versioned contracts, requirements, quality risks, threat model, privacy controls, evaluation gates, budgets, SLOs and AI-disabled continuity. Write failing tests for prohibited actions before implementation.

## Phase 4 — Build

Implement the narrowest viable three-workflow POC. Start with deterministic reconciliation and schemas. Add retrieval only with authority and provenance. Put model inference behind a replaceable interface. Add only bounded, approved and human-confirmed tools; side effects remain disabled in the assessed mode.

## Phase 5 — Break and recover

Run all public fixtures plus participant-created edge, subgroup, multilingual, malicious-document, poisoned-tool, stale-authorization, oversized-context, outage, checkpoint, replay and recovery tests. Show failed gates block release and that manual operation remains safe.

## Phase 6 — Transfer and defend

Complete production-readiness, operating model, vendor exit, retirement, roadmap and runbooks. Perform a clean-room handover. The final defence must link every material claim to immutable evidence and state residual risk and the next decision required.
